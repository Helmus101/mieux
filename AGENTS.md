# AGENTS.md

## Rules every skill and agent must follow

These apply to every task and every skill (design, backend, data, deploy). They override a skill's own instructions where they conflict.

1. Never modify working functionality without understanding its dependencies (callers, tests, stored data, the web and Expo clients that share `shared/`).
2. Never introduce a dependency without justifying it (what it replaces, its size and licence, why the platform or an existing package is not enough).
3. Never fabricate product, price or nutritional information. Missing stays null or "unknown"; examples shown to users must be real, dated data.
4. Never deploy without passing the relevant tests (backend pytest, web tsc + vitest + build, `npm run test:a11y` for UI changes).
5. Never mark a task complete without verifying its actual behaviour: run it, look at the result, and say what was not checked.
6. Never expose API keys or sensitive user data: no secrets in git, logs, URLs or third-party requests; session ids and purchases stay private.
7. Never make destructive database changes without a migration and a recovery strategy (backup or the timestamped index copies, and a tested way back).
8. Never sacrifice accessibility or mobile usability for visual appearance: 44 px targets, contrast, labels, reduced motion, no horizontal scroll at 390 px.
9. Always consider performance, security and maintainability when implementing features.
10. Always document important architectural decisions (in this file, `DESIGN.md` or `docs/`), with the reason, not only the result.

This file contains learned information about the Mieux project for AI agents.

## Project Overview

Mieux is a personalized grocery decision-support product with:
- Backend: FastAPI + SQLAlchemy (PostgreSQL/SQLite)
- Web: React + Vite + TypeScript
- Shared: TypeScript package for common code

## Commands


## Open Food Facts local copy and alternative search

The API reads products from `backend/off_local.db` (built by `scripts/import_off_dump.py`). Alternatives are chosen over
whole categories through the compact side index `backend/off_quick.db`; rebuild it after importing a new dump:

```bash
cd backend
. .venv/bin/activate
python scripts/build_quick_index.py     # ~20 s for 1.1 M products
python scripts/build_type_index.py      # indexes every product by Mieux type (off_type); run after the OFF import
```

Without those files the API still works: it falls back to OFF category tags and name search. `build_type_index.py`
matters most for the large share of OFF records that have no `categories_tags`; use `--min-scans 1` for a faster partial pass.

## Database Migrations

To create a new migration:
```bash
cd backend
alembic revision -m "description"
alembic upgrade head
```

## Core Principles

1. No hidden composite score
2. Missing nutrient values remain null (never treated as zero)
3. Allergens are hard exclusions
4. Unknown means unverified (not safe)
5. Alternatives must be same-category by default
6. Per-100g comparisons only
7. No unverified price claims
8. Purchases ≠ consumption
9. Deterministic receipt parsing (no LLM for arithmetic)
10. User must confirm receipt product matches

## Retailer-Specific Receipt Parsing

Supports 9 major French retailers:
- Carrefour, Monoprix, Leclerc, Auchan, Lidl
- Aldi, Intermarché, Franprix, Casino

Each has custom date patterns, total keywords, and skip keywords in `backend/app/receipts.py`.

## Authentication

There is none: the app is web-only and anonymous. Every request sends `X-Session-Id`
(auto-generated by the web client, persisted in storage) and that session id is the user.

## Environment Variables

Required for backend:
- `DATABASE_URL` - PostgreSQL or SQLite connection string
- `ALLOWED_ORIGINS` - Comma-separated list of allowed CORS origins
- `OFF_USER_AGENT` - User agent for Open Food Facts

## Markets (France and United States)

The app sends `X-Country: FR|US` on every call (profile setting, default FR). `app.state.off` forwards to that market's own Open Food Facts copy:
`off_local.db` + `off_quick.db` (France) and `off_local_us.db` + `off_quick_us.db` (United States). Build the US copy like the French one, with a country:

```bash
cd backend
OFF_COUNTRY=united-states OFF_LOCAL=$PWD/off_local_us.db .venv/bin/python3.9 -m scripts.import_off_dump ~/Downloads/en.openfoodfacts.org.products.csv
OFF_LOCAL=$PWD/off_local_us.db OFF_QUICK=$PWD/off_quick_us.db .venv/bin/python3.9 scripts/build_quick_index.py
```

`soldInFrance` on a product means "sold in the request's market" (name kept for cached rows). Chains live in `retail.py` / `chains.py`; `retail.in_market()` keeps each market's chain list separate. Community prices (Open Prices) are per market too: `op_local.db` (France, EUR) and `op_local_us.db` (US shops, USD), built with
`OP_COUNTRY=US OP_LOCAL=$PWD/op_local_us.db .venv/bin/python3.9 -m scripts.import_prices_dump data/prices.jsonl.gz data/locations.jsonl.gz`.
Prices are held in the market's currency (`market.currency()`), sentences are localised with `market.localize_money`, and category price estimates exist for France only.
Code that fans out to a `ThreadPoolExecutor` must use `_ctx_map` so worker threads keep the request's market.


## Mieux taxonomy and classifier (departments > categories > product types)

`backend/app/mieux_taxonomy.json` is generated: `app/data/taxonomy_base.json` + `app/data/taxonomy_ext.txt`, compiled by
`python -m scripts.build_taxonomy` (also writes `docs/TAXONOMY.md`). Edit the ext file to add departments (`D|`), categories (`C|`)
or types (`T|`), never the JSON.

`taxo1000.classify(name, generic_name, brand, categories)` places a product with `app/taxorules.py` + `app/data/taxo_rules.txt`
(`TARGET<TAB>NAME_REGEX<TAB>TAG_REGEX[<TAB>NAME_VETO]`, text lowercase/accent-free; `pâté` is normalised to `patee` so it never mixes
with `pâte`). Rules are ordered specific -> general; `python -m scripts.order_taxo_rules` keeps "non précisé" and broad `C:`/`D:` rules last.
Matching: the earliest-named rule wins, tags decide when the name only mentions an ingredient, catch-all tags never beat a specific name,
and ingredient/dish/chocolate/alcohol/sauce guards stop a flavour word from claiming the product. The result is the deepest justified
level: 3 = type, 2 = category, 1 = department, 0 = unclassified (never forced).

Tools: `scripts.eval_taxonomy` (coverage, name-vs-tag agreement), `scripts.review_taxonomy D_16` (examples per type in a department),
`scripts.audit_types` (suspicious placements per type), `scripts.make_taxonomy_sheet` / `scripts.score_taxonomy_sheet` (hand-labelled accuracy),
`scripts.build_taxonomy_index` (parallel, ~20 min for 1.1 M products; writes `off_taxo` + `off_tax`). Tests: `tests/test_taxonomy_rules.py`
(rules resolve + `tests/data/taxonomy_golden.json`). Add a golden case for every misplacement you fix.
